# 08. 通信协议与数据安全

## 1. 帧格式

帧头、帧尾、命令码、数据长度、字段偏移和校验方式必须使用具名常量或结构化定义，例如：

```c
#define UART_FRAME_HEADER  0xFFU
#define UART_FRAME_TAIL    0xFEU
#define UART_PAYLOAD_SIZE  9U
#define UART_TASK_INDEX     8U
```

不要在业务代码中大量直接使用 `0x31`、`0x34`、`Serial_RxPacket[8]` 等无法从上下文理解的值；历史协议兼容时应在协议头文件中集中说明。

## 2. 缓冲区和长度

- 每次写入数组前检查目标长度。
- 每次读取接收帧字段前检查当前帧长度和状态。
- 缓冲区满、帧头丢失、帧尾错误、未知命令和超时都必须恢复到可接收状态。
- 字符串必须保证 `\\0` 终止，并使用带长度限制的格式化接口。
- 禁止对外暴露可被任意模块直接修改的通信缓冲区；确需共享时应说明读写时机。

现有代码中的 `sprintf`、固定索引读取和阻塞发送属于历史实现特点，新增代码不得复制这些风险。

## 3. CAN

- CAN ID、帧类型、数据长度和分包规则集中定义。
- 发送接口检查 `len` 的合法范围，避免长度下溢或越界。
- 接收中断只负责取帧和置位事件，协议解析放在非中断上下文。
- 多帧发送必须明确序号、最大有效载荷、发送失败和超时策略。
