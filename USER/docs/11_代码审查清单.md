# 11. 代码审查清单

提交新增或修改代码前，至少检查以下内容：

## 1. 工程和文件

- [ ] 是否只修改了任务范围内的文件？
- [ ] 新文件是否已加入 Keil 工程？
- [ ] 是否误改 `FWLIB`、`CORE`、第三方 SDK 或自动生成文件？
- [ ] 头文件是否有唯一且不保留的保护宏？
- [ ] `.c` 文件是否优先包含对应头文件？

## 2. 命名和类型

- [ ] 新增函数是否使用模块前缀和 `snake_case`？
- [ ] 变量是否表达含义、状态和单位？
- [ ] 是否优先使用固定宽度类型？
- [ ] 是否正确使用 `const`、`static` 和 `volatile`？
- [ ] 公共接口是否只在头文件声明一次？

## 3. 外设和中断

- [ ] 初始化顺序是否完整且参数集中？
- [ ] GPIO、复用、波特率、定时周期、CAN ID 是否有明确说明？
- [ ] 中断是否足够短，是否避免了延时和复杂业务？
- [ ] 中断标志是否正确清除？
- [ ] 共享数据是否存在竞态或非原子读写？

## 4. 通信和安全

- [ ] 帧头、帧尾、命令码、长度和字段索引是否使用具名常量？
- [ ] 数组、字符串和 FIFO 是否有边界检查？
- [ ] 是否避免无边界 `sprintf`？
- [ ] 错误帧、超时、溢出和未知命令是否能恢复？
- [ ] 所有轮询是否具备超时或安全退出策略？

## 5. 控制和运行时

- [ ] PID 周期、角度、速度、位置和加速度单位是否明确？
- [ ] PID 积分和输出是否限幅？
- [ ] 电机和舵机是否有安全初始状态？
- [ ] 主循环是否出现不必要的深层阻塞？
- [ ] 故障状态是否会关闭危险输出并提供指示？
