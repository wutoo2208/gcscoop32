# 02. 文件与目录规范

## 1. 文件命名

新建项目文件使用小写 `snake_case`：

```text
motor_control.c
motor_control.h
uart_protocol.c
uart_protocol.h
```

文件名应体现模块职责，不使用 `new.c`、`test2.c`、`temp.c` 等无语义名称。历史文件如 `PWM.c`、`OLED.c`、`LED.c` 可以保留，以兼容现有工程配置。

## 2. 头文件保护

新头文件使用不带保留标识符的全大写保护宏，推荐格式：

```c
#ifndef PROJECT_MOTOR_CONTROL_H
#define PROJECT_MOTOR_CONTROL_H

/* declarations */

#endif /* PROJECT_MOTOR_CONTROL_H */
```

不得使用以两个下划线开头或以下划线加大写字母开头的自定义宏，因为这些标识符可能属于编译器或标准库保留空间。历史头文件的保护宏保持不变，修改时应避免产生宏冲突。

## 3. C 文件的 include 顺序

项目自有 `.c` 文件推荐按以下顺序包含头文件，并用空行分组：

```c
#include "motor_control.h"

#include <stdint.h>
#include <stdbool.h>

#include "stm32f4xx.h"
#include "stm32f4xx_conf.h"

#include "pid.h"
#include "delay.h"
```

规则如下：

1. 先包含本文件对应的头文件，尽早暴露声明不一致问题。
2. 再包含 C 标准库头文件。
3. 再包含芯片、CMSIS 和 ST 外设库头文件。
4. 最后包含项目模块头文件。
5. 同一个头文件只包含一次，不重复包含。

## 4. 接口与实现

- 对外使用的函数、类型、宏和枚举必须在模块头文件声明。
- 只在当前 `.c` 文件使用的函数和变量必须使用 `static`。
- 不在多个 `.c` 文件中重复手写同一个函数原型。
- 头文件不得包含不必要的实现代码、可变全局变量定义或大段字库数据以外的业务实现。
- 头文件只暴露调用者真正需要的内容，避免将内部状态结构体和内部宏全部公开。
