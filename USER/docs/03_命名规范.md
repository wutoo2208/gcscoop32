# 03. 命名规范

## 1. 通用原则

名称必须表达对象的职责、单位或状态。命名优先使用英文，项目已有的中文拼音接口作为历史兼容项保留；新增接口不得继续扩大拼音缩写的范围。

## 2. 函数

项目新增函数统一使用“小写模块前缀 + 动作”的 `snake_case`，例如：

```c
void motor_init(void);
bool motor_set_speed(int16_t rpm);
bool uart_protocol_receive(uint8_t byte);
```

推荐约定：

- 初始化：`<module>_init`。
- 反初始化：`<module>_deinit`。
- 设置：`<module>_set_<item>`。
- 获取：`<module>_get_<item>`。
- 更新：`<module>_update`。
- 处理：`<module>_process`。
- 查询状态：`<module>_is_<state>` 或 `<module>_get_state`。
- 中断入口必须使用芯片启动文件规定的精确名称，不得自行改写。

历史函数如 `Serial_Init`、`PIDInit`、`board_init` 可以继续被调用，但新增模块不再混用首字母大写、无分隔词和不带模块前缀的写法。

## 3. 变量

- 局部变量使用小写 `snake_case`，例如 `rx_length`、`target_angle`。
- 全局变量必须带模块前缀，例如 `serial_rx_flag`、`pid_state`。
- 计数器应使用有意义的名称，如 `index`、`retry_count`、`elapsed_ms`，避免大量使用上下文无法解释的短名。
- 布尔状态使用 `is_`、`has_`、`enable_`、`valid_` 或 `*_flag` 表示，并统一取值约定。
- 指针使用所指对象的语义命名，如 `packet`、`buffer`、`servo`，不依赖单个字母表达含义。

## 4. 宏、常量和枚举

- 宏使用全大写 `UPPER_SNAKE_CASE`，例如 `UART_RX_BUFFER_SIZE`。
- 可替代宏的数值优先使用 `static const` 或枚举。
- 引脚、地址、命令码、帧长度、超时时间和 PID 周期必须定义为具名常量。
- 枚举成员使用模块前缀，避免不同模块中的通用名称冲突。
- 宏参数必须加括号，宏不得产生隐藏的多次求值副作用。
