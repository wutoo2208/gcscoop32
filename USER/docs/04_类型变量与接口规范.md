# 04. 类型、变量与接口规范

## 1. 固定宽度类型

新增代码优先使用 `<stdint.h>` 和 `<stdbool.h>`：

```c
uint8_t  rx_byte;
uint16_t pulse_width;
uint32_t timeout_ms;
int16_t  motor_rpm;
bool     frame_ready;
```

`u8/u16/u32` 是当前工程的历史兼容类型。新增接口不得在同一模块中无理由混用两套类型；修改旧接口时，除非同步修改所有调用方并验证工程编译，否则保留原类型。

## 2. `const`、`static` 和 `volatile`

- 不会被函数修改的输入缓冲区和字符串使用 `const`。
- 只在当前文件使用的变量、函数和常量使用 `static`。
- 被中断修改、主循环读取的标志和数据使用 `volatile`，并明确说明生产者和消费者。
- `volatile` 不能替代互斥、临界区或原子操作；多字节共享数据需要保证读写一致性。
- 不使用 `__IO` 代替对变量读写关系的设计说明。与 ST 库寄存器交互时遵循库接口要求。

## 3. 全局变量

全局变量是例外而不是默认方案。新增模块应优先使用模块内部状态和访问函数；确需跨模块共享时：

1. 在定义文件中只定义一次。
2. 在头文件中使用 `extern` 声明。
3. 写明数据单位、有效范围、更新上下文和并发关系。
4. 不把多个模块的状态集中暴露到一个公共头文件。

## 4. 函数接口

- 无参数函数必须显式写 `void`。
- 指针参数必须说明是否允许为空、指向的元素数量和读写方向。
- 返回值必须表达成功、失败、超时或实际数据，不能让调用者猜测 `0/1` 的含义。
- 长度参数使用无符号固定宽度类型，并在函数入口校验长度。
- 函数只承担一个清晰职责；硬件初始化、协议解析、业务决策和运动控制不得无界混合。
