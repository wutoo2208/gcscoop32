# 01. 当前代码特征

以下内容是对现有代码的客观归纳，不代表所有历史写法都应继续沿用。

## 1. 文件组织

- 大多数功能采用同名 `.c/.h` 文件配对，例如 `PWM.c/PWM.h`、`OLED.c/OLED.h`、`pid.c/pid.h`。
- 头文件普遍使用宏形式的 include guard，但宏命名存在双下划线、大小写和拼写差异。
- 外设驱动通常包含初始化函数、发送/控制函数和中断服务函数。
- 部分代码来自教程、厂商模板或第三方 SDK，文件头注释和命名风格与项目自有代码不同。

## 2. 命名风格

工程中同时存在多种命名形式：

- 模块初始化：`Serial_Init`、`PWM_Init`、`OLED_Init`、`PIDInit`、`board_init`、`uart5_init`。
- 驱动接口：`can_SendCmd`、`Serial_SendByte`、`set_zhuashou_Angle`、`car_move_distance`。
- 类型和变量：`PID`、`Servo_t`、`Serial_RxPacket`、`RxState`、`fAngle`。
- 中断函数遵循启动文件约定，例如 `USART1_IRQHandler`、`TIM2_IRQHandler`、`CAN1_RX0_IRQHandler`。
- 部分业务函数使用中文拼音或拼音缩写，如 `fangzhi`、`yuantai_na`、`jixie_reset`、`wukuaipingtai`。

新代码必须采用统一规则；旧接口不得为了命名统一而随意改名，避免影响 Keil 工程引用、协议调用和中断向量绑定。

## 3. 类型和数据组织

- STM32 头文件提供了 `u8/u16/u32` 等历史别名。
- 项目代码也广泛使用 `uint8_t/uint16_t/uint32_t/int32_t` 等固定宽度类型。
- 控制算法大量使用 `float` 和少量 `double`。
- 通信和传感器模块使用固定长度数组保存帧、寄存器和接收缓冲区。
- 一些模块通过 `extern` 暴露全局状态，例如接收包、PID 状态、CAN 接收对象、FIFO 和 IMU 数据。
- 中断与主循环间部分数据使用 `volatile` 或 `__IO`，但使用并不完全一致。

## 4. 注释和文档

- 代码中同时存在中文注释、英文注释、ST Doxygen 模板注释和第三方版权说明。
- 注释常用于说明 GPIO、外设参数、协议帧和运动参数。
- 部分旧文件和 README 存在编码显示异常；新增文件统一使用 UTF-8 编码。
- 已有代码存在被注释掉的大段实验逻辑。新增代码不得以大段注释代码代替版本管理或设计说明。

## 5. 运行模型

- 工程以裸机初始化和主循环为主。
- 外设接收和周期控制主要通过中断完成。
- 主循环和运动控制函数中存在延时、轮询和等待标志的阻塞式流程。
- 串口和 UART5 使用接收状态机识别帧头、数据和帧尾。
- CAN 中断负责接收帧并置位标志，主流程再读取数据。
- PID 和舵机控制由定时器中断周期性更新。
- 业务流程由 `main.c` 中较长的顺序控制逻辑组织，存在多层 `while(1)` 和固定等待时间。
