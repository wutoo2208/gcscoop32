# 00. 适用范围与工程概况

## 1. 文档目的与适用范围

本文档根据工程目录内现有 C、头文件、启动文件、Keil 工程配置和已有说明文件整理而成，采用“现状总结 + 推荐统一规则”的形式。

本文档的目标是：

- 保留现有工程的编译和硬件兼容性。
- 让新增代码具备一致的命名、接口、注释、时序和错误处理方式。
- 降低中断、串口、CAN、PID、PWM 和运动控制代码之间的耦合。
- 使代码能够被其他开发者快速定位、调试和复用。

本规范适用于项目自有代码。`FWLIB`、`CORE`、ST 官方模板文件和第三方 SDK 文件属于外部代码或基础代码，除非确有移植、配置或安全需求，不应直接改写其实现。

本次规范编制不要求重构已有代码。历史代码可以继续保持原有接口，但新增代码和被主动修改的代码必须逐步遵守本文档的推荐规则。

## 2. 工程基础信息

当前工程具有以下特点：

- 目标芯片为 STM32F407ZG。
- 内核为 Cortex-M4，工程配置使用 168 MHz 主频和 FPU。
- 使用 Keil MDK 工程文件 `USER/Template.uvprojx`。
- 使用 STM32F4 Standard Peripheral Library，预定义宏包括 `STM32F40_41xxx` 和 `USE_STDPERIPH_DRIVER`。
- 使用 CMSIS 启动文件、ST 标准外设库和项目自定义驱动模块。
- 当前工程主要采用裸机方式运行，未启用 RTOS。
- 外部库和编译产物分别位于 `FWLIB`、`CORE` 和 `OBJ` 等目录。

## 3. 目录职责

| 目录 | 主要职责 | 代码特点 |
| --- | --- | --- |
| `USER` | 系统入口、启动配置、中断入口、工程级流程 | `main.c` 负责顶层流程；部分中断入口也位于此目录 |
| `SYSTEM` | 系统基础服务 | 延时、系统宏、USART1 通信、通用串口封装 |
| `Hardware` | 硬件抽象与控制算法 | PWM、舵机、开关量、PID、底盘运动控制 |
| `can_ZDT` | CAN 和 ZDT/Emm_V5 电机控制 | CAN 初始化、收发、FIFO、电机协议、运动封装 |
| `imu` | 惯性传感器驱动及 SDK 适配 | USART2 接收、协议解析、寄存器和传感器数据转换 |
| `lanya` | UART5/蓝牙或人机通信 | 帧接收状态机、命令发送和任务码传输 |
| `ckp` | USART6/人机界面通信 | 文本和字节发送接口 |
| `OLED` | OLED 显示及软件 I²C | GPIO 模拟 I²C、字库显示、定时刷新 |
| `LED` | LED 输出和指示 | GPIO 初始化、翻转和状态指示 |
| `FWLIB` | ST 标准外设库 | 外部基础库，保持原始接口和实现 |
| `CORE` | CMSIS 内核和启动代码 | 外部基础代码，保持原始接口和实现 |

模块依赖应尽量遵守“上层调用下层、同层少互调”的原则。业务流程放在 `USER`，硬件寄存器访问放在驱动模块，协议解析放在通信模块，控制算法放在控制模块；不要在 `main.c` 中重复实现外设寄存器初始化。
