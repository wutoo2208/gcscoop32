# 09. 错误处理、外部代码与历史兼容

## 1. 返回值

新接口统一使用可读的状态码或布尔值，调用方必须检查结果。推荐使用模块级枚举：

```c
typedef enum
{
    MODULE_STATUS_OK = 0,
    MODULE_STATUS_BUSY,
    MODULE_STATUS_TIMEOUT,
    MODULE_STATUS_INVALID_PARAM,
    MODULE_STATUS_OVERFLOW,
    MODULE_STATUS_ERROR
} module_status_t;
```

保留第三方 SDK 已有的 `WIT_HAL_*` 等状态码，不在适配层和 SDK 层之间混淆含义。

## 2. 超时和故障

- 外设初始化失败、通信超时、帧校验失败、FIFO 溢出和电机异常必须有处理路径。
- 轮询循环必须有最大次数、最大时间或硬件状态退出条件。
- HardFault、BusFault、UsageFault 等异常处理应保留安全停机和故障指示能力。
- 运动控制故障时优先关闭电机输出，避免继续发送运动命令。
- 错误信息应包含模块、错误类型和必要的上下文，不在中断中直接打印复杂日志。

## 3. 可维护性

新增代码不得引入：

- 未使用的函数、变量和头文件。
- 重复函数声明或重复包含。
- 未说明单位的控制参数。
- 大段注释掉的旧实现。
- 隐藏的全局状态修改。
- 没有上限的数组访问、字符串拼接或循环。
- 依赖特定调用顺序却没有注释或接口约束的函数。

## 4. 外部代码与历史兼容

以下内容默认作为外部代码或历史代码保留：

- `FWLIB` 中 ST 标准外设库实现。
- `CORE` 中 CMSIS 内核和启动文件。
- `USER/system_stm32f4xx.c` 等 ST 系统模板实现。
- `imu/wit_c_sdk.c`、`imu/wit_c_sdk.h` 等第三方 SDK。
- `Emm_V5` 等电机协议参考实现。
- 已经被 Keil 工程文件引用的历史文件名和公共函数名。

对外部代码的修改必须满足以下条件：

1. 有明确的芯片适配、编译修复或安全原因。
2. 记录来源、版本和修改原因。
3. 不把第三方接口风格扩散到新的项目模块。
4. 修改后重新验证工程编译、启动和相关外设功能。
