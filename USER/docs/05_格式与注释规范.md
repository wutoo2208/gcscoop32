# 05. 格式与注释规范

## 1. 代码格式

- 新增代码使用 UTF-8 编码。
- 使用 4 个空格缩进，不使用 Tab。
- 左花括号与控制语句或函数声明同行。
- 每行原则上不超过 120 个字符；长参数列表应换行并对齐。
- 一行只写一条语句。
- 运算符、逗号和控制语句关键字两侧保留适当空格。
- 不保留行尾空格，不使用无意义的大量空行。
- `if/else/for/while` 即使只有一条语句也必须使用花括号。

推荐格式：

```c
if (frame_length > UART_FRAME_MAX_LENGTH)
{
    return UART_STATUS_INVALID_LENGTH;
}

for (uint16_t index = 0U; index < frame_length; index++)
{
    protocol_process_byte(frame[index]);
}
```

## 2. 文件头和公共 API 注释

项目自有文件应在文件头说明模块职责、硬件资源、通信接口和维护信息。公共函数至少说明：

- 函数用途。
- 参数含义、单位和有效范围。
- 返回值含义。
- 是否允许阻塞。
- 是否可在中断中调用。
- 是否修改全局状态或硬件输出。

推荐格式：

```c
/**
 * @brief  设置电机目标速度。
 * @param  rpm 目标速度，单位 rpm，范围 -2000~2000。
 * @return true 设置成功，false 参数超出范围或通信失败。
 * @note   不得在中断服务函数中调用。
 */
bool motor_set_speed(int16_t rpm);
```

## 3. 行内注释

注释优先解释原因、时序、硬件约束、协议约定和单位，不重复描述显而易见的语句。所有魔法数字都应通过常量或注释说明来源，例如：

```c
#define MOTOR_CONTROL_PERIOD_MS 50U
#define OLED_I2C_ADDRESS        0x78U
```

无效实验代码应删除或通过版本控制保留，不得长期堆积在源文件中。
